# 连续经营场景运行器

通过系统正式 HTTP API 推进模拟业务，源码不会直接写业绩、工资、订单或财务表。管理员在工作台的“业务演练”页查看事件、预期值、实际值和失败原因。所有新增对象标注“模拟”，合成手机号为 000 前缀，收付款均为模拟记账。

## 如何执行

先在专用演示服务器环境设置 `BUSINESS_SIMULATION_ENABLED=true`，并重启 Go。仓库 Secrets 配置 `CC4_SIMULATION_ADMIN_PHONE`、`CC4_SIMULATION_ADMIN_PASSWORD`、`CC4_SIMULATION_SEED`（至少32字符的随机值）。仓库 Variable `CC4_BUSINESS_SIMULATION_ENABLED=true` 后，`Business simulation` 工作流可以手动运行，也会每天北京时间 00:15 推进到新的业务日期。

首次运行回放最近7天。之后读取已完成日期，逐日追加入职、录单、审批、回款、费用、调级和离职，重复运行不会再次录入已完成业务。管理员密码变更后，需要更新同名 Actions Secret；不要把真实管理员密码写进命令、源码或报告。

本机 CLI 可从受保护的进程环境读取相同凭据：

```sh
CC4_SIMULATION_ALLOW_WRITE=true python3 app/simulation/run.py \
  --base-url http://150.5.143.32:8080/cc4/api/v1 --days 7
```

`--days` 只决定首次回放起点。已有场景使用持久化起点，后续最大补跑31个日期。业务日期采用 Asia/Shanghai，避免浏览器/运行器所在时区改变业务日。

## 核对与恢复

- 每个成功事件持久化完成标识；中途停止后可跳过已经完成的事件，继续同一业务日。
- 每次业务写入前先保存 pending 事件，再调用业务 API。结果不确定时停止，保留现场；确认实际落库结果后由管理员处理检查点，不自动重发可能已成功的写请求。
- acquire、renew、release 分离。旧任务不能通过续约重新取得已经失去的执行锁；模拟写请求携带执行编号，服务端在每次写入前校验，并限制该请求执行时长，拒绝陈旧任务覆盖新状态。
- 模拟团队的经理执行月度汇总与收入同步，不重建其他团队的数据；已存在的工作日配置（包括合法空配置）保持原样。
- 状态和报告使用私有系统设置 `business_simulation_*`。仅管理员可读取报告或更改这些键；公开设置接口排除该前缀。密码由私有种子确定性派生，种子、密码和令牌不写入报告。

运行器每个业务阶段都回读核对：3/5/8单分别提成30/70/160元；待审不入账；审核/驳回/撤销即时核对收入；100元应收按30+70回款并拒绝超收；70元离职工资的重复发放、撤销、再发放始终对应唯一月度工资支出。

## 验证范围

`bash app/scripts/test-simulation.sh` 在新建 `cc4_test_*` 库中启动真实 Go API 与独立外呼模拟服务，完成7日回放、幂等重跑、非模拟月记录保护和1元故障注入；退出后删除该库和上传目录。SQL仅用于测试库初始化和明确的故障注入，不作为演练业务实现。

17个 Python 单测覆盖不确定写入、已完成事件恢复、空日历保护、部分初始化恢复、金额损坏检测、丢失执行锁写入拦截，以及工资撤销、取消费用、旧状态索引缺失、上游缺少可跟进线索、总额正确但逐笔回款收入错误等反例。Go集成另覆盖执行锁过期/交接、陈旧请求、报告权限，以及后续晋升或重新进入旧等级时历史工资不变。

当前状态格式为version=2，保留既有存储键以识别早期版本。旧版或缺失完整财务索引的状态会停止并报告需要迁移，不会把遗漏的费用/回款默认为0，也不会自动清空后重新录入。已有分配的外呼线索不会被强行转走；无可由演练销售跟进的线索时该步骤明确失败。

每次推进之前先回读已完成日期的销售、提成、逐笔回款、应收余额、运营费用和工资支出；通过后再写入新日期。报告显示核对后的累计流入、流出与净额。外呼、审核订单和客户档案通过同一合成手机号串联，成交后更新线索转化状态。

工资保留现有“按所算月末有效等级”口径，并按同一月末限制 C/B 补贴起点；后续职级变化不能把上月已赚补贴重算为0。本次没有新增未经确认的同月多等级分段计薪规则。通过报告只证明列出的场景和口径；不代表真实银行到账，也不证明所有业务组合都已穷尽。
