# 金标准场景（Golden Scenarios）v1

> 用途：Go 重写引擎的验收基准。每个场景给出**输入 → 期望输出**，期望值来自已确认的业务规则（cc4-callcenter/design.md），不来自旧代码的输出——旧代码有已确认的口径分歧（D1–D7）。
>
> 用法：`test/golden/cases.json` 逐条驱动 Go 引擎；同时喂给旧 JS 引擎产出「差分报告」。Go 与规则的差异 = 实现错误；Go 与旧引擎的差异 = 旧 bug 或口径分歧，须逐条裁决。
>
> 状态标记：✅ 口径已确认（可直接断言）｜⚠️ 依赖口径裁决（先裁决再断言）

## 域模型约定（所有场景共用）

- 「工作日」来自 `workday_config` 逐月配置，不是自然日
- 场景中的工作日序列显式给出，不依赖真实日历
- 金额单位：元（整数），提成/工资计算不引入小数

---

## A 组：日提成（模型一，日汇总公式）— 4 个场景

| # | 名称 | 输入（当日订单数） | 期望输出 | 状态 |
|-|-|-|-|-|
| G01 | 边界-1单 | 1 | 10 元 | ✅ |
| G02 | 边界-3单 | 3 | 30 元 | ✅ |
| G03 | 边界-5单 | 5 | 70 元 | ✅ |
| G04 | 高产-8单 | 8 | 160 元 | ✅ |

补充断言：0 单 = 0 元；公式 `n≤3: n×10；4–5: 30+(n−3)×20；≥6: 70+(n−5)×30`。

## B 组：C 级固定工资（前 3 天 × 30 封顶）— 3 个场景

| # | 名称 | 输入 | 期望输出 | 状态 |
|-|-|-|-|-|
| G05 | 3天内转正 | C 级工作日序列 [d1,d2,d3]，当月全部 | 固定工资 90 元（3×30） | ✅ |
| G06 | 宽限期白干 | C 级第 5 天才晋升 B（序列 [d1..d5]） | 固定工资仍 90 元（只算前 3 天，d4–d5 为 0） | ✅ |
| G07 | 跨月续领 | 10月 C 级最后 1 个工作日 + 11月前 2 个工作日 | 10月：30 元；11月：60 元（3 天额度跨月补足） | ✅ |

G07 同时是**旧引擎回归点**：JS 版实现正确（`max(0, 3 − 已领)`），差分应为 0。

## C 组：B 级 88 元（6 天总量 vs 每月配额）— 2 个场景

| # | 名称 | 输入 | 期望输出 | 状态 |
|-|-|-|-|-|
| G08 | 月中晋升跨月 | 10/26 晋升 B，10月余 3 工作日（26/29/30） | 10月：264 元（3×88）；11月：264 元（剩余 3 天额度）；11月第 4 个工作日起 0 | ✅ 文档口径 |
| G09 | 旧引擎对照 | 同 G08 输入喂旧 JS 引擎 | 预期旧引擎 11 月输出 528 元（6×88，每月重置） | ⚠️ D1 裁决：文档口径 vs 代码口径。演示裁决结果决定 G08 期望是否修订 |

G08/G09 的差分就是演示的「抓出现网 bug」高潮：**新引擎 264 vs 旧引擎 528，每月多发 264 元**。

## D 组：A 级薪资（底薪比例 + 全勤 + 绩效）— 2 个场景

| # | 名称 | 输入 | 期望输出 | 状态 |
|-|-|-|-|-|
| G10 | 全勤高产 | 当月 22 工作日全出勤；月订单 130；按日订单序列算提成 | 底薪 2200 + 全勤 400 + 绩效 1000 + 提成（逐日累加） | ✅ |
| G11 | 请假折算+无全勤 | 22 工作日出勤 18 天；订单 80 | 底薪 2200×18/22 = 1800；全勤 0（18<25）；绩效 300；+提成 | ✅ |

边界断言：订单 75/100/125 恰好落在档位下限（300/600/1000）；出勤 25 天在 22 天的月份不可能全勤（短月规则）。

## E 组：等级流转判定（状态机 dry-run）— 3 个场景

输入 = 最近 N 个工作日订单序列 + 当前等级 + 已工作天数；输出 = 目标状态或保持。

| # | 名称 | 输入 | 期望输出 | 状态 |
|-|-|-|-|-|
| G12 | C 晋 B 边界 | C 级第 3 天，近 3 日 [1,1,1]=3 | → 待晋升（b_level） | ✅ |
| G13 | C 淘汰边界 | C 级第 7 天（>6），近 3 日 [1,1,0]=2 | → 建议淘汰 | ⚠️ D6 裁决：文档「第 6 天结束时」vs 代码「>6 才触发」。按文档口径第 7 天初已淘汰；按代码口径第 7 天检查仍在岗 |
| G14 | A 降级 | A 级，近 6 日合计 12（=12，非 <12） | → 降级 c_level（≤12 即降，G14 钉死「=12 也降」） | ✅ |
| G15 | A 零业绩特例 | A 级，无任何业绩记录 | → 降级 c_level（代码行为） vs 保持（业务合理解释：休假不是降级理由） | ⚠️ D4 裁决 |

（编号到 G15，实为 12 个断言组 + 3 个裁决项；裁决项落定后并入正式用例。）

## 差分测试协议（Differential Protocol）

```
金标准 cases.json ──┬──▶ Go 新引擎 ──▶ 结果 A
                    └──▶ JS 旧引擎（cc4-callcenter 现网代码，本地起服务）──▶ 结果 B
A vs 规则期望 = 实现验收
A vs B 逐条对比 = 差分报告（每条差异标注：旧 bug / 口径分歧 D# / 环境差异）
```

差分数据源：cc4-callcenter 已有的随机游走脚手架（200 员工 × 12 月）产出真实分布数据，导出为 JSONL 喂双引擎。

### 结论

1. **业务逻辑零回归**：双引擎在所有薪资场景（除刻意修复的 D1）金额完全一致。
2. **D1 实锤入档**：T2 差分 176 vs 440，按种子推演每月多发 88×(工作日数-顺延余量)，真实资金风险。
3. **发现旧引擎新越权**（T9）：JS 版 /salary/calculate 无角色限制，employee 可算任何人薪资；Go 版 403。此为对齐时的修复项，已记入差分报告。
4. **健壮性**：注入、并发、分页、缺配置全过。
