# 学员交付模板

将本模板复制到自己的提交说明中，填写实际结果；示例基线数字不能冒充自己执行的证据。

## 交付信息

- 仓库与commit：
- 自己的演示地址、部署版本：
- 验收业务日期/时区：
- 本地验收命令与退出码：
- GitHub Student acceptance运行链接或证据包下载：
- 未提交代码标记dirty是否为false；若不是，说明原因并补充最终commit复跑：

## 自动验收证据

- `REPORT.md`和`summary.json`：
- HTTP业务集成实际执行组数与MCP结果：
- 首跑：覆盖日期、入离职/调级/回款/工资事件、通过与差异数：
- 完整重跑：7类业务数量前后对比：
- 无关团队月记录前后对比：
- 1元反例：哪条断言失败？预期多少、实际多少？为什么整套验收仍应通过？
- 流入、流出、净额及明细核对：
- 临时容器/数据库清理结果：

## 界面展示（另行人工验证）

- 当前业务日经营概览有数据，七日趋势与验收报告一致。
- 员工能看到职级生效历史，离职后不能登录。
- 审批待审/通过/驳回与业绩、收入变化一致。
- 财务页面能展示30+70的分笔回款、应收余额、费用与工资流水。
- 桌面和390px宽度无页面级横向溢出；关键操作能用键盘完成；错误、空结果、加载状态明确。

## 讲解问题

1. 为什么HTTP200/201不能单独证明回款或工资逻辑正确？
2. 预期金额从哪里来？如何避免用被测代码给自己“证明”？
3. 为什么要故意改错1元？如何区分检测到目标错误与随机连接失败？
4. 重复运行、重复批准和重复发工资分别怎样证明没有副作用？
5. 本次哪些规则有证据，哪些仍未覆盖？同月调级采用什么工资口径？

## 缺陷与边界

列出已发现问题、修复commit、修复前失败/修复后通过证据，以及未覆盖的规则和外部集成。
