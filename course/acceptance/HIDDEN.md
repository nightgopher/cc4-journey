# 隐藏变体：讲师评分用

公开剧本学员可以反复跑，所以完全可能被"背答案"。评分时，讲师用秘密种子另外生成一批 L3 结构的变体：业务形状与 08 演练相同，但金额、日期、晋升时机都不同。针对公开剧本硬编码的系统会在这里失败。

## 变化的参数

| 参数 | 范围 |
|---|---|
| 起始日期 | 2026-01 至 08 月内；**偶数号变体强制跨月**（七日窗口跨过月末） |
| 资深销售每日订单 | 0–12 单，**含 0 单日**（录 0 单也算出勤） |
| 成长销售每日订单、新销售订单、结算员工订单 | 1–8 / 1–4 / 1–8 单 |
| 晋升时机 | C→B 在 D1–D4；B→A 在其后某天，或不晋升 |
| 半天出勤、请假 | 半天 0–2 天，请假 1–2 天 |
| 应收金额、首款比例、超收幅度 | 50–500 元、10%–90%、超出 1–30 元 |
| 每日运营支出 | 10.00–200.00 元，带分 |

## 期望值从哪来

1. **规则模型**：`examples/toy_system.py` 按 D1 的两种裁决各执行一遍；两种裁决结果不同的字段，生成 `by_decision` 分支。这个模型已在全部公开剧本上与讲师 CC4 对齐。
2. **双引擎差分**：评分前，必须让讲师 CC4 通过参考适配跑同一批变体。两个引擎结果一致，期望值才算成立；不一致时逐条裁决，做法与 GOLDEN.md 的差分协议相同。

## 讲师操作

```bash
export CC4_HIDDEN_SEED='只有讲师知道的长随机串'
python3 course/acceptance/tools/hidden_seeds.py --count 6          # 写入 course/acceptance/hidden/（已 gitignore）
CC4_REFERENCE_REV=HEAD bash course/acceptance/adapters/cc4-reference/run-reference.sh --scenarios course/acceptance/hidden
# 差分通过后，对学员系统评分：
python3 course/acceptance/accept.py --scenarios course/acceptance/hidden --adapter ... --adapter-cmd ... --manifest 学员的adapter.json
```

- 同一个种子总是生成完全相同的变体，换种子就是一批全新变体。`manifest.json` 只记录种子指纹，不记录种子本身。
- 建议每期课程换一个种子；评分结束后可以公开当期变体，供学员复盘。
- `CC4_REFERENCE_REV=HEAD` 用已提交版本构建讲师系统，不受 `app/` 中未提交改动的影响。

## 差分发现（2026-10-27，开发种子，生成器 v2，8 个变体，CC4 已提交版本 cffd7aa）

6 个变体两个引擎一致，2 个不一致，根因相同：

**CC4 把同月已发工资合并成一笔流出，日期取最后一次发放日**（`app/internal/repo/payroll.go`：金额 `SUM(net_salary)`，日期 `MAX(payment_date)`）。于是一次发放会改写同月其他发放的现金流出日期：

| 变体 | 情况 | 本区间流出 |
|---|---|---|
| 5（06-26 起） | 06-22 已发过一笔 6 月工资，06-26 再发一笔，22 日那笔被挪到 26 日 | 多出 70 |
| 8（03-02 起） | 03-30 已发过一笔 3 月工资，03-02 再发一笔，合并后日期仍是 30 日 | 少了 70 |

规则卡 R10 写的是"已发工资按发放日期计入流出"，所以这属于 CC4 的偏差。公开剧本每月只发放一次，所以没有暴露。

**已裁决并修复**（分支 `feat/attachments-tos`）：规则卡不变，CC4 改为每笔已发工资一条流出（`salary-record-<工资记录ID>`），日期就是该笔的发放日期；重复发放保留原发放日期；迁移 `005` 把历史上按月合并的流水拆成每笔一条。修复后，公开剧本加这 8 个变体共 24 个场景、1400 项检查全部通过，`verify.py` 的 16 个阶段也全部通过。

覆盖面：同一批变体上，9 种错误实现全部被判失败。单跑公开 L3 只能抓到其中 4 种；隐藏变体靠跨月窗口和 A 级请假，多抓到了额度跨月、历史月份、请假优先、录 0 单出勤这几类。
