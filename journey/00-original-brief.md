# 00 · 客户原始需求（逐字记录）

> 记录说明：以下内容为客户的原始口述，**逐字保存、未做任何加工**。它就是本次研发流程的唯一输入起点——刻意保持模糊，因为真实需求从来如此。
>
> 记录时间：2026-10-26

---

我们是做教育体验课电话销售的，有不少销售，分几个团队。现在客户跟进、员工出勤、每天的业绩，还有月底工资，都是用表格和群消息在管，比较乱。

比如客户加了微信没买，后面交给谁跟、最后算谁的业绩，有时候说不清。员工每天报了多少单，主管还要核对。我们员工也分不同等级，新人和老员工的待遇不一样，等级还会根据表现调整，算工资的时候就更麻烦，经常要翻前面的记录。

我想做个系统，把这些事情串起来。销售能自己录东西、查自己的业绩和工资，主管能管团队，财务月底能把账算清楚，不用大家拿着几张表来回对。

具体要做哪些功能我还没想清楚，你可以先问我，咱们一起把需求理一下。

---

## 原始需求里能直接读出的信息（仅做索引，不展开设计）

| 维度 | 客户提到的事实 |
|-|-|
| 业务 | 教育体验课电话销售 |
| 组织 | 多名销售、分几个团队、员工分等级 |
| 痛点 1 | 客户跟进归属不清（加了微信没买的客户，后续谁跟、业绩算谁） |
| 痛点 2 | 每日业绩靠群消息报数，主管人工核对 |
| 痛点 3 | 员工等级会随表现调整，跨期记录导致算工资麻烦 |
| 角色线索 | 销售（自己录、查业绩工资）、主管（管团队）、财务（月底算账） |
| 现状工具 | 表格 + 群消息 |
| 期望 | 一个系统串起来，不要来回对表 |
| 明确未定 | 「具体要做哪些功能我还没想清楚」——客户主动要求先被提问 |

最后一条是关键：**客户明确邀请 AI 先提问**。这决定了 01 阶段的形态——不是猜测需求，而是结构化澄清。
