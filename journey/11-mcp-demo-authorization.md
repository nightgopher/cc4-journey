# 演示版 MCP 身份与权限设计

状态：**已实现并上线（2026-10-27）**。账号绑定凭据、动态授权、真实操作者、个人中心入口及 PostgreSQL 集成验收均已完成，见 [发布验收记录](12-mcp-user-auth-release.md)。

## 目标与取舍

演示时用户只需复制一次 Agent 接入配置，之后不用因 Token 定期到期反复操作。服务端仍能区分调用身份、限制工具与数据范围，并即时撤销访问。

采用 **绑定 CC4 用户的长期接入 Token**，演示版不设置自动过期，不增加刷新令牌、OAuth 授权服务器或第三方统一登录。它是面向支持自定义 Authorization Header 的 Agent 的演示接入凭据，不宣称实现了完整 MCP OAuth 授权流程。

每个演示身份各有一把 Token；复制员工 Token 代表员工身份，复制经理 Token 代表经理身份。不能用同一把管理员 Token 分发给所有角色后，再依赖客户端上报的角色区分权限。

## 用户使用流程

1. 用户登录 CC4，进入个人中心的“Agent 接入”。
2. 选择“仅查询”或“允许业务写入”。默认仅查询；写入能力始终受账号现有业务权限限制。
3. 点击“生成接入配置”，复制包含远程 MCP URL 与 Token 的配置到 Agent。
4. 以后持续使用，MCP 断线或会话过期由客户端重新初始化，Token 无需更换。
5. 点击“断开 Agent”后凭据立即失效；重新生成时原凭据失效，复制新配置即可。

演示版每个用户只保留一把有效凭据，不增加多客户端凭据管理页面。管理员可以为指定演示账号生成配置，普通用户只能为自己生成。非管理员请求中出现其他 ownerUserId 时明确拒绝。

## 登录态与凭据的关系

复用 CC4 登录态来确认“谁有权生成接入配置”，生成的接入 Token 再绑定该用户。无需让用户在另一套系统中重新注册。

Agent 软件自身的登录态属于另一个身份系统。没有事先建立可信身份对接时，CC4 无法据此确认 CC4 员工身份，或得知该客户端何时退出、过期。客户端传入 userId、role、isLoggedIn、expiresAt 等字段均不能作为授权依据。

因此，演示版不依赖“客户端是否过期”判断有效性：服务端检查接入凭据是否撤销、绑定账号是否有效，以及该账号当前拥有什么权限。用户退出 CC4 网页、网页 JWT 到期、MCP 连接断开，不自动撤销已授权的长期接入凭据；账号停用、员工离职或主动断开 Agent 则生效。

若未来掌控 Agent 客户端，可接入统一身份或受信授权交换；面向通用 OAuth MCP 客户端时，再增加标准授权与客户端自动刷新。届时也不应要求用户定期手工复制访问令牌。

## 每次调用的授权规则

**有效能力 = 用户当前业务权限 ∩ 接入模式（仅查询 / 允许写入）**。

- 用户身份、角色、员工与团队归属来自服务端查询，不来自 Agent 的工具参数。
- 复用 Web 的业务授权策略，包括职位模块权限、本人/团队/全局数据范围和操作权限；不另外维护一套含义不同的 MCP 角色规则。
- `tools/list` 只列出当前允许的工具；`tools/call` 再次检查操作及具体业务对象，不能靠隐藏工具名实现授权。
- 权限收回、凭据撤销、账号停用必须影响下一次请求和工具调用，已有 MCP 会话不能继续沿用旧权限。
- MCP 会话绑定凭据身份；不能携带另一用户的 Token 复用既有会话。
- 业务写入的 submittedBy、approvedBy 由服务端填入真实操作者员工 ID；不继续使用 0，也不允许客户端随意指定。

| 工具 | 查询模式 | 业务与数据约束 |
|---|---|---|
| commission_preview | 可用，需具备相应业务查看权限 | 参数试算，不读取他人业务数据 |
| employee_get | 按账号权限开放 | 本人资料、团队资料或全局资料分别复用相应业务策略 |
| salary_preview | 按薪资查看权限开放 | 员工本人、经理团队、其他角色既有授权范围 |
| level_transition_check | 按业务权限开放 | 参数试算与真实员工查询分开检查；真实查询必须检查目标员工范围 |
| workday_get | 按工作日查看权限开放 | 不因为工具为查询就绕过现有模块权限 |
| performance_submit | 不可用 | 可写模式仍需现有管理员/代录权限和目标员工范围；普通员工不能借此绕过自录审批流程 |
| performance_approve | 不可用 | 可写模式仍需现有订单审核权限及目标订单/员工范围，保留业务状态检查 |

## 最小页面与接口

页面只增加“Agent 接入”区块：当前连接状态、仅查询/允许写入、生成或重置配置、断开 Agent。明文 Token 仅生成时展示；找不到原配置时重置，不从服务端读取旧明文。

已复用现有登录认证的 REST 接口：

- `POST /api/v1/mcp/credentials`：生成或重置。默认绑定当前用户；仅管理员可指定 ownerUserId。
- `GET /api/v1/mcp/credentials`：返回当前用户的凭据元信息；不返回 Token 或哈希。管理员管理他人凭据需独立检查权限。
- `DELETE /api/v1/mcp/credentials/{id}`：本人或管理员撤销，重复撤销保持成功语义。

增加专用凭据表，最小字段为 id、user_id、label、token_hash、token_prefix、access_mode、created_at、last_used_at、revoked_at。使用足够随机的不可预测 Token，服务端仅保存哈希。每用户一个有效凭据，重置操作原子撤销旧凭据并生成新凭据。

审计记录用户 ID、员工 ID、凭据 ID、工具、业务对象、成功/拒绝结果。客户端自报名称可以作为辅助信息记录，不用于决定权限。

## 演示落地顺序与验收

1. 先完成凭据绑定、动态业务授权和两项写工具的真实操作者注入。
2. 增加轻量的个人中心接入区块，并生成可复制的 Streamable HTTP 配置。
3. 为演示员工、经理、管理员分别生成凭据；Actions 使用单独的仅查询凭据。
4. 将现有无用户归属的全工具集成 Token 迁出普通接入并停用，避免保留绕过新权限的路径。

必须验证：查询凭据无法直接调用写工具；篡改 employeeId 或订单 ID 无法跨团队；权限改变后同一 Token 的下一次调用生效；撤销后旧 MCP 会话返回未授权；普通用户不能替他人发放凭据；员工无法利用代录通道跳过自录审核；生成与重置流程不泄露历史明文凭据。

实现在独立工作区完成；不覆盖另一会话的业务实现。新增 `003_mcp_credentials.sql` 为兼容增量，旧全局 Token 不再作为鉴权路径。
